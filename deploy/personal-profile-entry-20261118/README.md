# 个人中心实际页面入口补修

## 原因

主入口 `index-new-information-fa1a2d10a628ef49.js` 的 lazy profile route 实际请求 `./Profile-Bb1hTfdM.js`。上一轮已发布个人统计组件和服务，却只更新另一个 `Profile-demand-personal-269...` 别名；真正入口别名在全局及三个 importer scope 内仍指向旧的 staff Profile，因此接口可用但页面仍显示旧“尚未配置”卡片。

这是入口可达性验收遗漏，不是财务规则、订单或收款问题。importmap 不会递归追踪另一个别名，scope 还会覆盖全局值；仅组件单测、检查另一个映射或接口成功不足以证明浏览器正在使用新组件。

## 精确修复

针对维护时最新 HTML 前像，同一真实请求别名的全局及三个作用域值，共四个精确 JSON 字符串，从旧 staff 模块改为已经发布的个人统计模块。其他全部 HTML 字节、全局/作用域映射、CSS、客户完整性及库存来源工作台改动不变。没有修改算法、API、库存、订单、回款或授权，没有重新编译入口或组件，也不重启进程。

`fix-profile-entry.py` 固定前像和两个内容寻址 Profile 名称，构建时核验四值、scope 完整语义保留及字节逆向；发布时以共享双锁、HTML CAS、实际 entry lazy 请求证明、组件 SHA、相关资源/API快照、12进程元数据快照、私有前后备份及原子写入保护。只在本轮自有新 HTML 哈希仍匹配时回滚，不覆盖第三方版本。脚本仅适用于捕获时前像，后续漂移应重新审查，不能改掉哈希后任意运行。

## 补充验收

`test-browser-resolution.py` 使用已有系统 Chromium，通过本地拦截全部请求，在同一 HTTPS origin 和真实 lazy importer URL 下解析捕获的原/新完整 importmap。旧 HTML 实际请求旧 Profile，新 HTML 实际请求新 Profile；测试涵盖 scope 优先级，而非自写解析器替代浏览器行为。它只验证真实浏览器模块路由，不假称执行完整生产入口或用户登录。

已发布新组件另通过原生 React/ReactDOM getter 11项回归，覆盖预计金额、待核、回款达标与发放未知状态、分页、月份/公司迟到响应及个人资料/安全操作。真实两个统计接口的受保护只读验收独立执行，业务指纹未变。相关真实金融结果、生产保护及详细切换回执只在私有任务/主机保存，不进入公开仓库。
