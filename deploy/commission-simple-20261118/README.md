# 个人提成页面简洁化

本轮只改变展示，不改变提成计算、规则版本、回款口径、身份授权、发放或历史订单。主视图保留“预计提成”“回款达标提成”两卡与六列表格；仅真实待核时显示徽标和具体原因。金额以十进制字符串安全显示两位小数。原业绩页精度及三卡不变。

订单号打开原生 Dialog 右侧详情，直接使用服务端返回的成本、费用、净利润和比例，浏览器不重算提成。规则版本、审计和来源信息只在详情折叠区；没有真实发放来源时不显示伪造的已发放金额。月份、公司、分页和主体围栏继续沿用原查询实现。

## 构建与验收

`packaging/build-commission-ui-proposal.mjs` 在明确的源码冻结后仅替换当前 Profile 模块的一个业务 factory；其余入口、导入、原生单例、个人资料及安全功能字节保留。源前像固定到本轮开始的 Git 提交，不采用并行编辑期间的活动源码充当基线。当前请求别名的全局及 scoped importmap 和既有业务 CSS 链接必须一并验证，不能只验证未使用的别名。

`packaging/check-commission-ui.mjs` 使用实际捕获的 React、ReactDOM、query 和 Radix 实现，围绕完整 Profile getter 运行合成回归。相关页面与查询测试覆盖两卡六列、具体待核、零与未知区分、版本不重算、侧栏关闭和焦点返回、迟到响应隔离及原资料安全流程。另行离线 Chromium 验证实际候选模块与正式基础 CSS，不用标记 stub 替代模块执行。

`validation/release.py` 仅新增一份内容寻址 Profile JS 和一份 CSS，并精准切换后台 HTML。双锁、全字节 CAS、原资源/进程环境保护、独立许可和 HTTPS 内容哈希为上线门禁。自身异常尝试精确自有后像回滚；诊断文件写入失败不得阻断回滚，第三方版本不得被回滚。其故障回归在 `validation/test_release.py`。

生产 bundles、私有保护清单、真实账号、订单或金额、环境配置、完整发布许可和业务回执不在本公开归档。工具中的执行目录仅用于运维复现，不是授权范围扩展。真实生产部署记录保存于私有维护空间。
