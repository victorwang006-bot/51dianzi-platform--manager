# 客户物料上传精简 · 2026-11-19

## 用户操作

常规表格：选择文件 → 核对 → 确认导入。常见列自动识别；无法识别或存在歧义时才显示字段匹配。错误行优先展示，缺品牌可批量补空白。币种必须明确选择一次 CNY，不猜默认值，也不重复勾选。价格、税务未知时不强迫填入猜测值。

上传记录直接“继续导入”原任务，不要求重复上传。没有确认批次的标准任务显示“待核对 / —”，不会把原表含表头的行数或全零统计当作已入库。完整任务号、哈希和诊断信息保留在折叠详情，不删除原证据。

## 安全与范围

仅改变原生客户工厂内 `T6`（BatchUpload）及 `z3`（HistorySession），其余工厂、辅助函数和当前 ECS `B3` 原文件幂等保护字节不变。管理端两份增量 JS 采用新哈希文件名；新增 CSS 仅包含 `.customer-upload-history` 下的覆盖规则。

后台 HTML 仅替换两种原 Workbench URL 的全部完整引用并增加一条独立 CSS 链接。前台页面、任务2资产、原所有静态资产、API、worker、DB、权限、环境和进程不改动。旧文件不删除。

已见确认批次后，详情和继续入口持续校验原确认/批次/行请求及冻结 payload 映射。映射丢失或变化时阻断，不下载原文件重建；同一请求的真实回执及 revision 变化允许推进。未知结果仍沿用原请求和原批次核实。

## 离线验证

最终源码六组定向回归：128 项通过。实际两份原生工厂的匿名交互：6 项通过。发布控制器：42 项临时目录安全回归通过。仅替换原生工厂 return 测试缝；真实 SheetJS、hooks、queue、schema 和辅助代码保留，外部 UI 与传输使用匿名 mock。

这些结果不是生产物料上传写测。本任务不创建测试库存、不改真实上传记录。

## 工具

- `packaging/build-native.mjs`：原生叶组件替换、ABI 与原字节逆向校验。
- `packaging/test-native.mjs`：匿名原生交互与详情映射丢失回归。
- `packaging/prepare-package.py`、`freeze-package.py`：冻结 HTML、CSS、资产和证据清单。
- `validation/release.py`：最新前像、原双锁、完整文件/进程保护、独立审核、单次切换与自身 HTML 的安全 CAS 回滚。
- `validation/test_release.py`：无需 ECS 的安全测试。

正式上线必须依次通过本任务的 fresh capture、独立冻结清单审核、只读 preflight 和单次 apply。完成状态以真实 `receipt.json` 中 `status=verified` 和已关闭的协调窗口为准。失败保留新增资产，不重放已开始的 apply，不回退任务2前台。
