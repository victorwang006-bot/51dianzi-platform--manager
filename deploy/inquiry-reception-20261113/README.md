# 工厂渠道统一询价接待：源码候选（2026-11-13）

本目录/分支是源码候选，**不是已批准的生产增量运行包**。不能把普通 `pnpm build` 的整套 dist 覆盖到 ECS。未执行生产数据库迁移、业务数据写入或服务重载。

## 用户交互

点击前台工厂库存“渠道”直接连接“51电子网 · 工厂渠道接待”会话，不增加数量/发送确认窗；登录和明确买方企业身份必须先就绪。点击才发起受权 mutation，预热/公开列表查询不创建会话。采购数量暂未知以待确认呈现。

实际服务端接待归属仍为库存真实业务责任员工或保留的明确分工，品牌不代替卖方身份、责任权限与参与人。普通个人会话不重新标为平台官方。混合工厂/普通询价会话保留实际对端标题，另显示平台工厂接待 scope。

## 生产部署前必须完成

1. 从两仓最新 main 和实时 ECS API/HTML/importmap/预热图读取底板，保存精确哈希；不能回铺旧导航、后台标题、加速或推荐资源。
2. 两库增量schema必须先备份并独立审批：主站 `scripts/apply-factory-inventory-inquiry-schema.mjs`；后台 `scripts/apply-official-stock-reception-schema.mjs`。均默认离线审阅；主站未经批准不带 `--apply`，后台脚本仅支持明确的loopback隔离fixture，正式DDL需另在批准的维护窗口执行经核验SQL，不能绕过其fixture门禁。不能自动修改任何历史单据、消息、管理员绑定或旧责任人。
3. 新配置库存需由有权人员明确选择可信本地商户映射；绑定/ERP接待权限/后台上下文+接待scope缺失显示待配置，不能用公司名称推断身份或自动授库存权限。
4. 校验生产只读来源连接支持所需共享行锁且有界等待；不支持时拒绝投递。跨库读锁租约配合主站事务重核，不伪称分布式事务。
5. 从实际生产运行包构造白名单API精确补丁及新内容寻址静态叶，独立证明非补丁字节/未授权模块不变，完成固定文件清单、依赖闭包、实际运行路径及回滚清单。
6. 固定候选审批后持 `/var/lock/dianzi51-public-deploy.lock` → `/var/lock/dianzi51-production-code.lock`，fresh CAS，原子替换/精确备份。只重载批准的平台及后台API实例，不重载任何worker或修改PM2环境/工作目录。
7. 失败只恢复本次精确替换文件，不能删除别人新增资产；DB新增字段含工厂NULL库存记录时不能逆改为NOT NULL或删除来源字段。应用回滚不能使工厂询价被当普通库存读取/交接，应保留受权兼容读或关闭新入口。

## 验证边界

源码类型检查、构建、DI/受控渲染和安全回归不等于真实登录账户的生产端到端验收。未在真实企业创建测试询价，未做正式报价/采购/交易。

## 接待预览口径

物料接待预览的新服务逻辑不创建询价、不更新发布投影，BFF跳过新增命令审计写；但整个RPC仍复用既有CRM准入门禁，原门禁含权限状态同步/历史关联协调分支，不能声称整条RPC绝对零DML。本轮DI不执行该真实门禁写分支，也未调用生产API。新草稿缺当前publication持久证据时明确pending；首次发布成功不等于接待已就绪，须按页面提示再次单项核验。
