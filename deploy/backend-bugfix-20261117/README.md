# 2026-11-17 后台商城、业务订单客户与采购入库修复

本轮为既有 ECS 项目的精准增量修复，不重新搭建或迁移网站，不以旧 GitHub 源码整站构建覆盖当前生产版本。

## 修复内容

商城型号联想至少输入 3 个字符，型号和品牌共同停顿 500 毫秒后请求；完整型号精确查询优先，未命中才查询字面前缀。大目录使用已有型号索引，原始候选窗口限制 80 行，返回最多 20 条去重资料；只填型号、品牌、封装，不自动填交易字段。联想只读查询不再跨目录 SQL 持有账号与成员写锁，查询前后仍复用原实时权限核验。失败可手工录入。保存仍是待上架，发布仍须显式确认。

一个有效官方团队时自动选择，并在保存时由服务端重新锁定校验；多个团队必须明确选择，没有团队或缺权限时明确拒绝。官方团队与业务团队是不同配置，不按相同主键推断权限，不自动给其他业务员工扩权。Victor 原超级管理员和业务组长身份保持，官方组长配置通过独立、带审计的维护步骤完成。

新建业务订单不默认加载客户名单；先搜索，默认服务端核验的当前有效业务团队及可信后台创建来源，没有当前成员团队则本人范围。具备企业读取资格的账号可主动切换全企业搜索，并如实展示创建者、负责人、记录团队与后台来源。缺少创建追踪的记录标明来源未核实，不称为测试或导入客户。本轮不迁移、删除、归档或重新分配任何客户，也没有未经要求的“近90天”时间限制。原 CRM 显式日期筛选保留。

采购入库错误 `it.number is not a function` 来源于实际动态模块依赖 ABI：根入口的 `z` 导出是 Radix Slot，不是 Zod。两个实际 Workbench 模块分别捕获已存在 schemas 模块的原生工厂，并只修正错误桥接。保留字段校验和库存业务规则。修复旧编译器映射后，避免后续重建再次接错。

## 构建与验证

`material/build-mall-repair-runtime.mjs <frozen-live-runtime> <new-output-directory>` 及 `material/build-mall-repair-leaf.mjs <frozen-live-leaf> <new-output-directory>` 钉住本轮真实生产基线哈希，定点生成商城候选，验证完整逆向恢复和未改写入门禁。输入是私有运维阶段冻结的真实运行模块；这些完整生产文件不提交 Git。

客户构建器位于 `../customer-picker-fix-20261117/`；主站的只读客户工厂构建器和服务回归在对应主站仓库。后台 BFF 输入校验和前台实际服务必须同时保留新的范围字段，不能只更新前端界面。

采购入库不仅检查语法或模拟 Schema：本轮使用最终联合模块、最终 importmap、真实下载的 React/ReactDOM/Zod 依赖，在隔离 JSDOM 中执行完整模块、getter 和完整组件。A/B 各通过 10 项，合法用例没有运行错误，没有真实网络或 mutation。旧 `.trim` 和 `null.length` 后续失败被证明是 overview/list 夹具违反服务端结果契约；负向控制仍能重现，没有为此改变生产库存逻辑。

这些是实际候选加载、隔离 SQL/DOM 和 ECS 文件/进程验收，不冒充浏览器登录后的真实业务写入验收。本轮不创建真实客户、商品、订单或入库单作为测试。

## 发布边界

统一候选只替换前台实际 API、后台实际 API、后台静态 HTML 三个文件，增加两个内容寻址运行时与三个叶子资源。保留旧 importmap 的所有键、未改映射、旧 scopes 与 HTML 其它字节，新公共模块复制其原有效 scope。保留旧资源，避免覆盖另一功能补丁。

发布采用有序双锁、39 个生产文件哈希及全部 12 个进程保护、独立审查哈希绑定、单次尝试、fsync 备份与原子替换。先添加资源，再 API CAS 和滚动重载，健康检查通过后最后替换 HTML。失败只回滚仍匹配本轮候选哈希的自有文件；他人版本不覆盖，也不盲目重载。不会执行 DDL、客户回填、权限批量修改、PM2 save/update-env、worker 或 Nginx 修改。官方团队维护单独记账，不能混称为无数据库写入的代码发布。

具体上线时间、提交和 ECS 回执以本目录的最终上线记录为准；仅有构建输出或本文件并不表示已上线。
