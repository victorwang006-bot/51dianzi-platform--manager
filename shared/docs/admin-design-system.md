# 后台设计与权限界面规范

## 视觉基准与 v18 字号升级（2026-11-04）

已上线的渠道库存继续是后台内容区的视觉基准。用户本轮明确批准业务文字“大一号”，仅升级后台业务内容和弹层的字号/常规控件；保留字体栈、颜色、结构、顶栏、Logo 和外层导航布局，不扩展为视觉重做。以下是当前 v18 规范，取代前版 12/11/15px 与 32px 控件规范；历史 v13～v17 的功能、权限、数据和发布回执不会因视觉规范修订而被改写。源码以 `AdminUnifiedSystem.css`、`ChannelInventoryHost.css` 和局部语义角色为准，禁止 `zoom`、`transform` 缩放或新增全局强制 `!important`。

### 作用域与复用规则

`AdminReadability.css` 的 `:root` 历史默认值不改，以免改变顶栏和侧导航。v18 token 只定义在 `.admin-unified-content`、真实业务 Portal 根和带 `data-admin-readability="true"` 的 body 挂载弹层/菜单上；员工 Sheet 也必须接入，不能只覆盖业务 Dialog。`--admin-content-*` 是该作用域专用的字号、行高和高度别名，业务共享副本保留其原前台 fallback；没有后台作用域时不会启用新版字号。`BusinessNativeTypography.css` 只桥接后台原生弹层中无 UI data-slot 的普通控件。既有局部 `!important` 角色规则只复用 token，不新增强制全局覆盖。

## 员工权限界面

采用五个真实页签：**员工资料、平台权限、渠道库存、业务ERP、账号与安全**。仅显示当前panel，而非多个内容块仍堆在同一长页。底栏统一“保存当前页”，只发送当前页改动，成功不自动关闭；其他页草稿保留。关闭有未保存修改时确认，换员工、换账号或会话清理必须隔离草稿及迟到响应。

平台权限按真实既有模块能力排列，无对应能力的单元格不能伪造一个按钮。业务ERP保留原ERP授权及原数据范围；不能把ERP默认本人范围误解释成官方渠道库存的团队设置。高风险停用、离职交接保持独立明确操作及原服务器校验，不能混入普通授权保存。

### 渠道库存的团队和授权

“渠道库存团队（业务团队）”直接复用现有业务企业、团队、成员和有效admin↔front绑定。已有“智捷团队1”须正确回显并可从同源团队列表选择；不另建同名官方团队，不因显示团队就自动授权，不通过姓名或当前访问者猜测关联。业务团队与原生库存权限是两个真实服务：各自保存结果分别反馈，部分成功不得笼统误报全部失败或全部成功。

原生查看、录入/编辑、发布、追加内部备注按既有权限含义独立展示。只改授权时保留原有官方成员状态（包括未分组null）；不得把业务teamId写入独立官方成员表。未分组账号的实际权限从真实targets回读，不能因members为空就显示未授权。新权限保存须携真实账号版本、保留原成员版本，并采用服务器成功回执作为新基线；冲突明确提示刷新，不能自动覆盖并发授权。

### 当前列表及负责人

查看当前渠道库存必须同时满足有效后台身份、独立查看授权、真实绑定、合法企业/商户/业务团队与记录级条件；不能靠赋予ERP库存管理权来假装解决只读访问。查看不等于编辑、发布、来源联系人或私人备注，UI隐藏不能代替服务端校验。改组、撤权、停用及绑定变化必须失效旧内容与旧弹窗。

表格在“型号/品牌”后增加**负责人**，固定96px，当前采用表头12px/正文13px。只显示严格原始录入证据对应的后台姓名；没有可信证据显示“待核实”，不取当前负责人、当前绑定、导入操作者或当前访问者猜名，不因显示列而回写旧归属。既有已确认Jack四条沿用原证据。新增一列后表格最小宽度1056px，保留原数量、报价和216px操作区，小屏横向滚动。

历史29条共享按用户明确授权，在新权限代码两端verified后，独立事务仅补原合法团队的缺失共享记录、必要库存revision/updated_at与追加审计；不覆盖旧共享、原始录入证据、业务内容或负责人，不迁移/新建团队，不批量放行来源/写权限。实际完成以正式代码发布和独立事务验收回执为准，文档不是上线证明。

## 所属行业与渠道操作（本轮功能）

渠道库存在“负责人”后增加**所属行业**，固定110px，当前采用表头12px、正文13px及表格容器横向滚动。该列仅使用当前库存关联渠道的真实 `industryCode`，按既有行业词典显示中文名称；历史空值或非法行业码显示“未设置”，不从渠道名称、型号、品牌或当前访问者推测，不回写历史行业。它是公开分类字段，不附带渠道身份、来源联系人或私人备注，也不改变来源读取权限。

渠道档案每行操作区统一为**上传库存 + 更多操作**。更多菜单依次为“查看库存、下载库存、编辑渠道、分隔线、停用/启用”；停用使用危险色并保留原二次确认。菜单通过现有组件的Portal展示，避免表格滚动区域裁切，支持键盘操作。禁用项明确说明只读、缺少权限、已停用或正在处理等原因，不出现无反馈操作。

行内“上传库存”预选当前渠道并复用既有表格读取、字段映射、预览和逐行提交流程。必须先取得真实库存写权限和精确渠道校验，不借渠道编辑权限绕过库存写权限；分页目标不会因未出现在首个渠道选项页而丢失。企业、账号、授权或页签变化清理等待状态和预选，并拒绝迟到响应。库存页保留“上传库存”和独立“单条上传”入口，原服务端校验和幂等重试不变。本轮不新增授权、数据库迁移、历史数据修正或团队共享写入。

## 客户供应库存与来源关联（本轮功能）

客户列表在“负责人”之后、“下次跟进”之前增加**供应库存**列，主操作为“上传物料表”；只有关联库存与合法来源查看权限同时存在时提供“查看库存”。行内上传、查看、补全档案、需求录入与跟进当前采用13px可点击文字，不显示矩形按钮边框或底色；保留键盘聚焦、禁用原因和可读标签。供应库存、下次跟进、需求和操作均需完整可达，表格在自身容器横向滚动，固定操作列不得遮挡需求入口；不压缩联系人到不可辨认。主录入按钮、筛选与页记忆不改，采购需求与供应库存含义分离。

客户档案统一维护关联来源的公司名称、所属行业和联系人；渠道档案继续保留作为供货来源管理视图，不再要求为同一客户重复手填公司资料。首次实际成功上传才建立显式客户—渠道关系，后续在原合法企业/数据归属/库存责任范围复用；既有独立渠道只能由有权用户明确选择关联，不按名称、电话或负责人自动合并，不将全部客户批量转换为渠道。关联来源中的重复公司字段由客户档案读取，渠道类型、供货启停等专属字段仍在渠道管理。必要行业缺失提示到客户档案补全。按用户2026-11-04明确要求，未关联客户首次上传默认类型为“工厂”，直接进入文件上传窗口，不再重复显示类型确认弹窗；已关联渠道保留真实原类型，不批量改历史数据。

上传复用原表格解析、字段映射、预览与幂等逐行提交流程。首次渠道、关联、第一条库存及原默认团队共享和真实创建审计须处于同一个数据库事务；取消或全部失败不产生空渠道。客户上传的恢复状态按企业、当前身份、授权和客户隔离，不与原渠道上传混用；不因迟到响应、未知网络结果或恢复重试另建库存。全成功才自动进入渠道档案并按真实渠道ID定位/高亮；部分成功先保留失败/未知行和重试入口，用户明确完成后可查看已上传结果。成功结果提供“查看该客户库存”，自动限定正确来源，不以同名搜索代替ID定位，也不绕过来源读取门禁。

客户负责人、渠道/库存责任人和原始后台上传人保持分离。客户可见不等于库存可上传或来源可见；读写均重校当前后台商户业务范围、员工绑定、CRM记录权限、官方库存授权、库存模块及有效团队。客户转交、归档、渠道停用或权限变更不得自动改写旧库存归属、原上传人证据或团队共享。此次仅新增独立的关联结构，不历史批量匹配、迁移业务内容、自动授权或启动数据库自动迁移。实际上线以两端正式发布回执和独立schema验收为准。

## 日常身份核验与稳定页面（2026-11-04修订）

后台工作台在登录后首次进入，以及账号或企业切换时取得合法身份和权限证明。正常浏览不进行30秒身份轮询，普通窗口焦点切换不重新核验；同身份路由返回复用内存证明，不将证明写入持久存储。浏览器历史缓存恢复属于安全重新进入，仍需重新核验；显式重试、退出登录、服务端返回会话失效或不明确安全拒绝时，按原安全路径清理旧身份、请求和权限。网络错误与真正身份/权限异常保留提示，日常后台处理不插入推挤表格的核验横幅。

客户供应摘要、供应权限读取和已打开上传窗口也不重复30秒轮询或普通焦点刷新；首次读取、客户/页/身份变化、上传完成和显式重试按需请求。实际查询、上传、编辑、停用和下载仍由服务端按当前授权逐请求校验，取消前端轮询不取消服务端鉴权。撤权后的空闲页可能直到下一次请求才更新，但该请求必须受当前权限约束，不能凭旧前端证明放行。

上传完成及查看库存后的精确渠道定位同样不因普通窗口焦点或30秒定时重新读取目标，避免加载状态把合法编辑窗和草稿清空。保留首次、身份/权限键及目标URL变化的真实ID读取、取消与迟到响应围栏；提供“重新核验目标”文字入口显式重试，错误、停用或真正身份/权限变化仍按原限制清理，不回退到其他同名渠道或全部库存。

## v19 客户个人星标与八列表格（2026-11-04）

本节是客户列表当前规则，取代上文仅针对客户列表“下次跟进”展示列的要求，其他历史业务与 v18 字号、颜色、弹层、文字操作规则不变。列表实际为八列：客户名称、所属行业、联系人 / 电话、等级 / 阶段、负责人、供应库存、需求录入、跟进。只移除列表日期的 col、表头、单元格及旧176px宽度，保留日期数据、客户详情、跟进记录、今日/逾期筛选及右侧跟进入口。表格最小宽度由1480px减至1304px；单一局部横向滚动，需求112px、跟进88px继续固定在右侧，不能用整页溢出或遮挡中间列代替可达性。

姓名与小星标同行 flex：姓名 min-width:0，可截断并以title保留全文；星标 flex-shrink:0，不能被长姓名推走。星标是独立原生button，24×28px无框透明点击区，16px灰色空心或黄色实心SVG，无新增矩形按钮、文字列或整行链接。姓名只打开详情，星标只改变个人偏好；支持原生键盘、可见焦点、aria-label、aria-pressed、aria-busy和禁用状态。保留正文13px、表头12px、标题16px、弹层标题18px及既有无框文字操作。

个人星标只采用服务器权威结果，默认当前真实员工。组长是否可代组员仅由独立customer.starContext的当前有效targets证明，不能从canManageAll、管理员标签或旧context.members推断。只有targets不止本人时显示“标星列表：我的 / XXX（组员）”；代组员时可提示正在为谁管理重点客户，列表使用scope=all、assignedUserId和starUserId均为该目标，仍保留关键词、等级、阶段、归档和跟进状态筛选。回到本人恢复原合法scope，不扩旧全企业开关权限；撤权或读失败不得静默回退本人并误写。

所有列表行必须继承服务器isStarred、starRevision、starUserId、canSetStar元数据。无偏好由服务器表示false/revision0；缺少新API、身份不匹配或元数据时不启用星标，其他客户操作仍可用。服务端在权限与筛选后、分页前全量星标优先排序；客户端不得对当前20条伪排序。设置和取消成功均重新读取列表并回到第一页，目标切换也回到第一页，尽可能恢复原行星标焦点，行不在结果时聚焦表格区域。

每次写入冻结显式目标、布尔值、expectedRevision、requestId及enterprise/actor身份。未知网络结果保留整份原请求供幂等重试，不能新建requestId或再次反转状态；等待时锁定星标控制器及目标选择。版本冲突提示刷新后重新选择，禁止自动覆盖组长/组员最新偏好。账号、企业、授权或目标变化取消旧请求并清状态，迟到回执不得刷新或修改新身份列表。不将个人星标或代设目标写入localStorage偏好。

BFF仅增加固定customer.starContext query与customer.setStar mutation，严格共享输入DTO，继续逐请求校验exact merchant、有效员工绑定和商户scope。setStar只是个人偏好，窄例外使用客户读取授权，不扩大其他客户写权限或全局module write开关；真正组长、目标和客户可见性仍由原生router/service权威复核。starContext与既有来源只读查询一样不新增业务command审计写入，真实星标写入保留既有转发审计。
