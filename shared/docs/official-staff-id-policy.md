## 强制规则

官方员工通过后台执行的录入、表格上传、编辑、备注及其他业务动作，其规范操作身份以**服务端当前登录的真实后台员工／管理员账号 ID**为准。显示姓名（如 Jack）、浏览器传入的 ID、当前负责人以及前台会员 ID，都不能替代后台操作身份。

服务端仍须实时验证该后台账号有效，并验证其当前企业授权、真实业务员工映射、团队和动作权限。前台员工 ID 是现有业务数据及权限模型的技术关联，不得把后台 ID 数值直接写入前台用户 ID 字段，也不得仅因两个 ID 数值相同而认定同一人。

记录应能区分原始录入／上传后台员工、后续修改后台员工与当前负责人。原始录入身份不可在转交负责人时被覆盖。本人资格以经服务端核验和可靠持久化的后台身份记录判断；组长资格以相关记录所属有效团队的当前组长身份判断，不以“平台管理员”等显示角色推断。

后台身份必须来自已认证服务器上下文及受保护的跨服务委派，不能信任表单、URL 或任意自定义请求头。所有官方动作保留后台操作人审计，同时保留必要的企业、前台技术映射、绑定版本、记录及请求关联信息。

## 历史数据

保留原始审计，不将历史前台 ID 直接改写成后台 ID。历史归属只能依据可验证的原始后台操作审计、请求关联及当时的绑定事实恢复。证据缺失或冲突不得猜测、批量归给现负责人，或以提高角色权限替代修复；须单独列出待核实项。

## 本轮实施范围

修复官方员工渠道库存及来源身份判定、员工菜单入口、业务局部拒绝被误判为整会话失效、来源弹窗闪退和重复核验。保留真实撤权、跨企业隔离、原有库存编辑和私人备注保护。任何必要结构变更均须单独受审，不重复执行已完成的行业或协作备注迁移。
