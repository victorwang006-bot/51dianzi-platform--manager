# 51电子网现有后台改版说明

## 当前状态

本次直接修改 `admin.51dianzi.com` 对应的现有仓库 `victorwang006-bot/51dianzi-platform--manager`，不是独立网站交付。此前独立 Demo 的开发已停止，未发布。原代码基线为 `3d6d7a02329db81c376d7441f51dd7f5bc08cb58`，本次改动保存在独立功能分支 `feat/admin-ui-unification-20261101`。

**线上网站尚未替换。** 本轮没有运行数据库迁移，没有调用生产写接口，没有修改真实员工账号、权限、库存、订单或企业归属。后端、数据库结构、生产部署脚本和依赖声明均保持不变。

## 已实现的界面优化

左侧导航按“库存管理 → 客户管理 → 采购管理 → 运营管理 → 系统设置”排列，运营保持独立分组。默认只打开当前页面所属分组，支持账号隔离的折叠记忆、旧状态迁移、整体图标栏、拖拽宽度和移动布局。原有通知角标、已读标记、懒加载和业务上下文参数仍保留。

顶部增加持续显示的面包屑和账号菜单，个人信息移入头像菜单。原平台订单、平台用户、客户列表和询价接待入口名称明确区分。人员入口合并为原站 `/staff` 的“员工与权限”，公司信息、员工操作记录和异常日志归入系统设置。旧 `/admins`、`/workbench/add-user` 和 `/profile` 路由继续保持原有授权与兼容，不在左侧重复列出人员管理入口。

员工中心使用真实接口返回的数据，提供查询、状态筛选、权限摘要和一个右侧设置窗口。已存在可信一对一关联的员工，可在同一窗口查看及按操作者实际权限设置后台运营权限、库存/客户/询价/采购等 ERP 权限、业务范围，并查看新增、撤销和角色/范围变更预览。窗口同时保留登录安全记录的查看能力。

平台订单页区分商城下单与内部销售、采购订单，增加筛选重置、全部状态切换和固定订单识别列/详情操作列。金额统计明确标注“含取消、退款订单；非实收金额”，并说明全量汇总不随列表筛选改变。

## 权限和账号的必要边界

后台账户与企业业务用户只通过服务端返回的活跃 `admin_business_staff_bindings` 一对一映射关联，禁止按姓名、手机号或后台 `userId` 猜测合并。未关联、查询失败、缺少业务 scope 或操作者无管理权限时，界面分别提示并禁用相应操作，不自动创建或迁移真实身份。

业务权限实际可用，需要活跃后台账号、有效关联、精确商户 BFF scope、企业成员 ERP 权限和业务范围共同满足。ERP 勾选项不代表业务工作台全部可用，后台原生权限中的历史 `business.*` key 也不能替代独立 BFF scope。本轮只读取这些关联与 scope，不授予、撤销或重新绑定它们。

后台账户接口仍要求 `admins.manage`。企业业务设置继续由当前操作者真实绑定的业务身份转发；保留所有者不可改、自己不可改自己、只能授予已有权限及全企业范围限制，不用超级管理员角色绕过企业授权。业务上下文和后续企业摘要必须对应同一个企业与业务员工，不匹配即停止成员读取和设置。若员工已有超出操作者可授予范围的权限，完整现状会显示并锁定，避免无关勾选引发隐式撤权。

现有保存没有跨服务原子事务。窗口按 ERP 权限、业务范围、后台设置顺序处理实际变更，并记录各步结果。部分失败不会关闭窗口或误报全部成功；已保存部分更新基线，未保存修改保留，重试不会重复已完成步骤。

## 尚未实施的事项

本轮完成界面入口与已关联员工的设置整合，**没有完成所有历史账号的身份迁移或物理合并**。新建后台账号暂时保留原站旧功能入口；员工邀请与企业业务交接继续使用原来的用户同意、验证码及交接流程。若要实现全部员工的一次性开户、自动关联和完整后台代管授权，需要先单独确认迁移规则并完善服务端编排，不应通过前端改名冒充已实现。

现有后台代管企业成员接口的旧 ERP 枚举，与企业业务 BFF 当前枚举存在版本差异。本轮复用当前业务 BFF 的完整权限字典，没有改共享授权契约。后续全量代管应先收敛契约。原业务工作台构建仍有较大分包警告，本轮没有扩大范围进行全业务模块拆分。

历史生产交接记录提示，源码完整重建与部分旧运行补丁并非已证明完全等价，不能只因构建通过就全量覆盖现网。上线前需核对当前静态根、运行版本与历史修复，选择保留现网既有功能的发布方式，准备备份与回退，并获得用户对具体发布范围的确认。
