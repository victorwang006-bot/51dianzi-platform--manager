## 一、项目概述

本项目为 **51电子网（51dianzi.com）电子元器件交易平台的后台管理系统**（dianzi51-admin），供平台运营人员使用，功能覆盖物料主数据管理、商户入驻审核与 CRM 管理、客户物料管理（含下架）、前后台消息互通以及后台账号管理。系统与前台门户（dianzi51-platform，由另一个 Manus 任务维护）部署在同一台阿里云 ECS 上，通过 Nginx 按路径分流，并通过共享 RDS 数据库实现跨系统数据联动。

## 三、功能模块清单

后台共 4 个一级菜单，路由与功能如下：

| 菜单 | 路由 | 功能要点 |
|---|---|---|
| 物料数据库 | `/` | 电子元器件物料主数据（型号/品牌/封装/参数/生命周期），初始为闭合搜索态，支持型号前缀搜索、分类与生命周期筛选、新增物料、参数档案（完整型号展示） |
| 商户管理 | `/merchants`、`/merchants/:id` | 商户入驻列表与详情。详情页为**折叠卡片设计**（物料管理默认展开置顶，工商信息/联系人/结算账户默认折叠）；企业工商信息卡片整合了营业执照（点击查看）、法人信息、签署协议链接；CRM 操作（通过/补件/拒绝/暂停）、销售负责人（salesOwner）；**已开通 CRM 的商户不再显示"通过/补件"审核按钮**；内嵌"物料管理"面板（见下） |
| 消息 | `/messages` | 前后台消息互通：前台"联系客服"产生会话（message_threads/messages 表），后台可回复；会话详情含客户信息、商户入驻/企业开通事件展示 |
| 用户管理 | `/admins` | 后台账号管理（admin_users 表，bcrypt 密码，角色 super_admin 等） |

### 3.1 客户物料管理（商户详情页内嵌）

这是最近几轮的核心功能，实现于 `client/src/components/admin/MerchantMaterialPanel.tsx` 与 `server/db.ts` / `server/routers.ts` 的 `platformMaterial` 路由：

- **列表**：跨库拉取该商户（按 creditCode 匹配）在前台发布的芯片物料，展示型号、品牌、数量、实拍图（点击查看）、发布人姓名与电话、状态；支持型号/品牌搜索、状态筛选（已发布/待发布）、分页。
- **下架**：仅对已发布物料可操作，**必须填写下架原因**（≤255 字）。下架 SQL 按对接方案执行：`status='draft'`、`publishedAt=NULL`、`offshelfBy='admin'`、`offshelfReason=原因`。下架后物料回到前台商户"待发布"列表并显示红色"平台下架：原因"提示，商户修改后可重新发布。
- 对接契约见 `docs/前台直连RDS物料数据对接说明.md` 及用户提供的《后台管理用户上传物料（含下架）技术支持方案》。

### 3.2 对外 API（供前台/其他系统调用）

## 四、数据库结构（dianzi51_admin 库）

核心表（定义见 `drizzle/schema.ts`，改表流程：改 schema → `pnpm drizzle-kit generate` → 应用 SQL）：

| 表 | 用途 |
|---|---|
| `materials` | 物料主数据（型号、品牌、封装、参数 JSON、生命周期、PINOUT 引脚图等） |
| `merchants` | 商户（入驻资料、工商信息、法人、营业执照、签署协议、crmStatus、salesOwner、creditCode） |
| `admin_users` / `password_reset_codes` | 后台账号与短信找回密码（阿里云 SMS） |
| `message_threads` / `messages` | 前后台消息会话与消息体 |
| `users` | 模板自带用户表（Manus OAuth，生产以 admin_users 自建登录为主） |
| `categories` / `products` / `orders` / `refunds` / `settlementBills` 等 | 早期电商模型预留表，当前业务未启用（平台无佣金模式，第18轮已移除佣金） |

前台 `dianzi51` 库中被后台跨库读写的表：`inventories`（物料，含 offshelfBy/offshelfReason 字段）、`companies`（企业，creditCode 关联）。

## 五、开发与部署流程

### 5.1 日常开发（Manus 沙箱）

开发在 Manus WebDev 项目中进行，改动后运行 `pnpm test`（当前 67 个用例全部通过）与 `npx tsc --noEmit`，通过 `webdev_save_checkpoint` 保存版本。`todo.md` 按"轮次"记录了全部 46 轮需求与完成情况，是最完整的需求史。

### 5.2 推送 GitHub（固定流程）

仓库使用双分支同步模式：`main` 为 Manus 检查点分支，`gh-sync` 为对外推送分支（基于 github/main 叠加改动，保持干净历史）：

```bash
cd /home/ubuntu/dianzi51-admin
git checkout gh-sync
git checkout main -- client server drizzle shared todo.md docs   # 拉取本轮改动文件
git add -A && git commit -m "feat/fix: 本轮说明"
git push github gh-sync:main
git checkout main
```

### 5.3 生产构建与部署（必读 `docs/生产部署构建说明.md`）

**关键约束：生产后台挂在 Nginx `/admin/` 前缀下，构建必须带 `VITE_BASE_PATH=/admin/`**（第38轮空白页事故的根因就是漏了这一步）：

```bash
cd /home/ubuntu/dianzi51-admin
VITE_BASE_PATH=/admin/ pnpm build
# 自检（三项必须通过）
grep -c '/admin/assets/' dist/public/index.html            # >= 2
grep -c '"/admin/".replace' dist/public/assets/index-*.js  # = 2
grep -c '="/".replace' dist/public/assets/index-*.js       # = 0
# 打包上传并重启
tar czf /tmp/admin-dist.tgz dist
scp -i <私钥> /tmp/admin-dist.tgz root@47.97.108.147:/tmp/
ssh -i <私钥> root@47.97.108.147 'cd /opt/apps/dianzi51-admin && \
  cp -r dist dist.bak.$(date +%m%d%H%M) && tar xzf /tmp/admin-dist.tgz && \
  pm2 restart dianzi51-admin --update-env'
# 验证
curl -s -o /dev/null -w "%{http_code}\n" http://47.97.108.147/admin/   # 200
```

部署后建议用浏览器实测登录后的核心页面（商户详情、物料管理面板）。历史部署均保留了 `dist.bak.*` 备份，可快速回滚。
