## 根因与最小修复

第一处故障是日期类型：数据库驱动将旧资料的 `establishedAt` 返回为 `Date` 对象，线上 `cnReviewDate()` 只接受 `YYYY-MM-DD` 字符串。复审在构造旧资料时抛出 `CN_REVIEW_CANDIDATE_INVALID`。仅将跨库 SELECT 的日期投影改为：

```sql
DATE_FORMAT(company.establishedAt, '%Y-%m-%d') AS establishedAt
```

没有改变数据库、全局驱动配置、日期严格校验或版本摘要。

解除日期错误后，完整详情验收发现第二处故障：详情读取也会抛出 `CN_REVIEW_LEGAL_CHANGE_REQUIRED`，前端因此只显示“审核详情暂时不可用”。第二阶段仅在详情函数中精确捕获该异常，返回原安全摘要并增加 `reviewBlockedCode`、`reviewBlockedReason`，同时令 `canReview=false`。其它主体、负责人、成员、账号及候选无效异常继续抛出。

`cnReviewAssertSubject()` 及整个 `reviewCnRegistrationDraft()` 写入函数与第一阶段基线保持逐字节一致。前端展示例外只接受准确的合法变更阻断代码；操作判定继续使用原始 `Oe(d)`，通过、退回、确认按钮及提交 handler 均保留不可审核保护。只新增一个内容哈希静态资源，并修改 HTML 的一条商户组件 importmap 映射，避免 immutable 缓存继续加载旧组件。
