# 生产版本基线与安全发布

## 只读版本采集

`scripts/production-audit.py` 使用 Python 标准库，只读取 PM2 状态、两份既有 Nginx 配置、实际入口 HTML/import map、运行时模块与字面量依赖文件哈希。不读取 `.env`、私钥、业务附件或数据库，不部署、不 reload、不删除文件。

在经授权的服务器直接运行以下命令，或将脚本内容通过已授权 SSH 的标准输入交给 `python3 -`。输出重定向到操作方本地，不把输出自动提交至仓库：

```bash
python3 scripts/production-audit.py --max-files 1200 --max-bytes 134217728
```

限制会写入 `scan.limited`；候选缺失路径可能来自注释、打包代码内字符串、共享 Nginx alias 或未使用代码，不能直接认定线上 404。computed imports、数据库迁移与真实业务行为仍需单独核对。脚本明确输出 `production_equivalence_certified: false`，不是“生产与 main 完全一致”的认证。

## 发布前必须完成

1. 记录实际前端、后台、worker 及运行模块版本，保留入口 HTML、import map 与哈希；不要只用目录日期或旧源码工作目录 HEAD 代表现网。
2. 在隔离环境从目标 Git 提交构建，对照现网功能范围，核对是否包含已上线热修复。构建成功不等于可以整包覆盖。
3. 通过质量 CI；集成测试仅使用显式授权的本地测试数据库，禁止传入生产凭据。
4. 确认可恢复备份、数据库迁移顺序和可执行回退路径；缺失证据时暂停实际发布，不擅自跑旧迁移或清空数据。
5. 取得本次具体上线范围授权后才切换制品，不将本轮治理整改自动部署到 ECS。

## 容量与历史制品

先采集当前运行目录及 Nginx root、worker 和 sidecar 的引用。所有当前引用目录及回退/备份目录应保护。确认未被运行服务引用、且备份可恢复后，再提出有明确文件清单的清理操作；不按目录日期直接删除。当前生产基线清单属于私有运行证据，应妥善保存而非公开发布。

## 分支保护

本轮只增加 CI 配置，不自动更改 GitHub 仓库权限、保护规则或部署策略。待 CI 实际运行通过后，由仓库管理员将对应 quality check 设置为 main 的 required check，并保留紧急恢复流程。
