## 二、本次完成范围

系统现已包含统一后台侧边栏，提供物料数据库、商户管理、消息中心和后台用户管理四个入口。物料模块具备列表、搜索、分类与生命周期筛选、详情、增改、启停、文件与图片管理；商户模块具备列表、详情、审核、CRM 状态、联系人与跟进记录，并在详情页内嵌客户物料面板。客户物料通过统一社会信用代码与前台数据库关联，下架操作要求填写原因，跨库不可用时会返回明确状态而不是阻塞页面。

消息中心支持前后台会话列表、类型和状态筛选、已读/未读处理及回复；后台用户管理支持列表、新增、编辑、角色更新、启用、停用与删除。本次修复了新增后台用户接口未返回完整账号实体和可靠 ID 的问题，并加入完整 CRUD 测试。

登录与权限方面，系统新增公开 `/login` 路由。未登录访问受保护页面时，URL 会重定向到 `/login?next=...`，登录后安全回到原目标页面，并阻止外部地址和登录页循环回跳。共享权限矩阵同时约束服务端 tRPC、前端路由与侧边栏；后台用户管理仅允许超级管理员访问。

| 角色 | 主要权限摘要 |
|---|---|
| `super_admin` | 全部模块读写与后台用户管理 |
| `operation` | 物料、商户、消息读写 |
| `merchant_mgr` | 商户与消息读写，物料只读 |
| `customer_svc` | 消息读写，商户只读 |
| `risk_control` / `finance` / `auditor` | 按职责提供相应只读范围 |

## 五、生产构建与 Nginx 配置

后台部署在 `/admin/` 子路径时，必须使用以下命令：

```bash
pnpm build:admin
pnpm verify:admin-build
```

仓库已提供 `deploy/nginx/dianzi51-admin.inc.example`。其中带尾斜杠的 `proxy_pass http://127.0.0.1:3001/;` 会在转发时去除 `/admin/` 前缀，使 `/admin/api/trpc` 到达后台的 `/api/trpc`。物料图片由 `/admin/uploads/` 独立位置提供，避免与前台路径冲突。

仓库同时提供 `deploy/ecosystem.config.example.cjs`，仅从服务器进程环境读取凭证。生产说明见 `docs/生产部署构建说明.md`。

| 环境变量 | 用途 | 要求 |
|---|---|---|
| `DATABASE_URL` | 后台数据库连接 | 必填，生产密钥 |
| `JWT_SECRET` | 后台会话签名 | 必填，生产密钥 |
| `PORTAL_API_KEY` | 前台对接接口鉴权 | 启用前后台对接时必填 |
| `UPLOAD_DIR` | 物料图片目录 | 建议 `/opt/apps/dianzi51-admin/uploads` |
| `PLATFORM_DB_NAME` | 前台跨库库名 | 默认 `dianzi51` |
| `SMS_*` | 阿里云短信找回密码 | 启用短信渠道时必填 |

## 六、交付限制与上线前事项

本次工作只完成代码集成、数据库基线、配置模板和验证，没有向阿里云 ECS 部署，也没有修改生产 RDS、Nginx 或 PM2。前台物料跨库查询需要在生产 RDS 用户具备对应库权限后验证；当前托管开发数据库不包含真实前台库，因此本地只验证了不可用状态与逻辑测试。

新建空数据库不包含本地密码管理员。若复用现有生产 RDS，可继续使用原有后台账号；若部署到全新数据库，必须通过安全的运维流程创建首个超级管理员，不能在代码或 SQL 文件中硬编码明文密码。

生产构建仍有单个前端 JavaScript 包约 1.03 MB 的 Vite 体积警告，不影响当前构建通过，但后续可按页面动态导入进行拆包优化。正式上线前还应在目标服务器执行 Nginx 配置校验、PM2 环境变量核验、数据库备份及回滚演练。
