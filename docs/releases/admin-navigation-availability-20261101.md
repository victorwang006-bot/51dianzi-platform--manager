# 后台业务导航稳定性修复

版本标签：`admin-navigation-availability-20261101-v1`。

## 问题与修复

现场首次包含 `auth.me`、`business.navigation`、未读消息、通知统计及物料分类的批量请求耗时约 11.1 秒；单独复测导航正常约 0.7～1.0 秒。原界面将导航数据尚未返回或错误后缺失能力视为无业务入口，且原接口会吞掉上游临时故障后成功返回空能力，因此业务菜单会暂时消失。

本版本仅将业务导航查询拆为独立 HTTP 读取，并复用原认证请求头、会话与凭据传递；根据当前账号隔离缓存，明确区分加载、临时故障、成功空权限和成功授权。临时网络、超时或服务暂不可用最多额外重试两次，明确登录/权限/业务域拒绝不自动重试。错误状态不沿用之前成功缓存的业务能力。

后台保持真实无授权、绑定撤销、ERP 不可用或空投影的拒绝结果。候选商户的传输、配置、超时、5xx 或解析异常使整次导航受控失败，不得剔除无法验证的商户后计算更宽交集。候选范围读取错误同样受控处理。所有原业务命令、商户范围、员工绑定、管理员角色及精确能力投影保持原规则。

仅对上述五个只读查询记录随机请求关联 ID、过程名、受控结果代码与耗时；导航另记录范围读取、授权及上游阶段耗时。计时不记录 Cookie、密钥、请求输入、响应正文、原始错误或 SQL，不观察写操作，也不得因日志失败改变查询结果。

## 发布前验证

2026-11-01，原 API 从原始 Git 基线重建后的 SHA-256 与现网 API 逐字节一致。修复通过完整 TypeScript 检查，12 个相关纯单元/mock 回归文件共 81 项测试全部通过，子域资源路径验证通过。没有连接生产数据库或执行数据库迁移、支付及真实业务命令。该结果不冒充全部外部/真实 MySQL 集成测试的通过记录。

## 发布范围与回滚

按前端静态资源、后台 Web API 两阶段发布。新内容散列静态资源新增保留，HTML 入口原子切换；历史资源不删除。旧 API 制品不覆盖，新 API 复用原依赖、环境及静态路径，仅滚动重载后台 Web 两实例。前台服务与五个 worker 不重启、不升级，不改变数据库、角色/范围配置、企业绑定或业务许可；退休功能边界继续保持关闭。每阶段具有独立状态指纹核验与原版本回滚点。
