## 本次完成

### 1. 单条录入复用已有型号联想

客户物料单条录入直接复用前台已有 `DemandPartNumberInput` 和 `customerDemand.suggestPartNumbers`，输入至少两个字符后进行 220 ms 防抖，最多展示八条候选，支持键盘选择和手工输入。选中候选时带入其非空品牌，候选没有品牌则保留手填品牌；品牌仍可修改。型号候选只修改录入草稿，不将字典 ID 当成库存 ID。

已补充同关键词刷新失败、旧候选、迟到响应、客户或权限变化的保护，避免旧请求回填当前表单。

### 2. 客户库存与“渠道库存”统一设计

客户详情库存沿用渠道库存的紧凑默认九列：型号、品牌、负责人、来源客户、可供数量、报价 CNY、渠道参考一、渠道参考二、操作。共用型号复制、参考价单元格、列布局和编辑展示面板；“编辑”和“更多”保持紧凑组织。

“来源客户”是这条库存的客户来源；“渠道参考一、二”是参考商城价格，两者分开。来源查看与编辑使用同一个已有授权 gate，继续限制为真实录入员工或有权管理组长，并与企业、库存写权限及 CRM 客户范围相交，不放宽权限。保留上轮已上线的参考价一、二手填功能、精确金额字符串及 CAS/UUID 防护。

提交中或结果未知时，普通焦点切换、刷新和分页不会丢失冻结的请求号与提交内容；真实身份、权限或客户版本失效仍会销毁旧会话。

### 3. 客户录入后同步展示同一库存

客户录入继续走正式客户上传接口，写入原 `channel_inventory_materials`。客户库存和渠道库存读取同一条记录、同一 `material ID`；没有复制库存、没有新增同步表，也不按公司名猜测渠道绑定。

共用上传完成路径刷新库存、渠道和批次缓存，同时保留客户页的本地刷新。显示仍受当前账号授权、搜索条件和页码影响；跨浏览器实时推送不在本次范围内。

另外修复了首次上传的空渠道边界：正式渠道和绑定已创建但还没有物料时，允许本人在原客户写权限及 write fence 成立、正式绑定重验且全原始物料集合确为零的前提下继续录入或恢复。没有用占位库存解锁，也不放宽已有物料的读取、来源或编辑权限。
